# Fortran 実装の乱数生成仕様

## 一様乱数生成器

`normal_rng_t` は依存ライブラリを使わない `xorshift64` 型の疑似乱数生成器を保持します。

状態 `s` は次のビット演算で更新します。

```text
s = s xor (s << 13)
s = s xor (s >> 7)
s = s xor (s << 17)
```

状態の上位53ビットを使い、0 と 1 の端点を避けた倍精度一様乱数 `u` を作ります。

```text
u = (real(ishft(next_u64(), -11)) + 0.5) / 2^53
```

状態が 0 の場合は固定の非ゼロ状態に置き換えます。
この RNG はベンチマークの再現性と速度を目的としたもので、暗号用途には適しません。
共通ベンチマークのサンプル生成シードは `0x5EED2021`
（10進数 `1592598561`）です。

## 標準正規乱数

`normal_algorithm_polar` は Marsaglia の polar 法で2個ずつ生成します。

1. `u` と `v` を区間 `(-1, 1)` から生成する。
2. `s = u^2 + v^2` を計算する。
3. `s <= 0` または `s >= 1` の場合は棄却して再試行する。
4. `a = sqrt(-2 log(s) / s)` を計算する。
5. `u*a` と `v*a` を標準正規乱数として返す。

この方式は三角関数を使わず、Box--Muller の直接法より標準正規乱数生成の計算量を抑えます。
奇数個の生成で余った値は保存し、次回の配列生成またはペア生成で最初に使用します。
空配列への生成では状態を変えません。
これにより、同じ総数なら配列の分割方法によらず同じ乱数列を得られます。

`normal_algorithm_ziggurat` は256層のZiggurat法を使います。
層境界から `k`、`w`、`f` のテーブルを一度だけ生成し、矩形内部の候補を整数比較だけで高速に受理します。
矩形外の候補は密度比較で再判定し、層0では指数分布を使って正規分布の裾を生成します。
矩形内の受理判定を小さな関数に分離し、コンパイラが配列生成ループへインライン展開しやすくしています。
棄却処理と裾の生成は別の関数にまとめ、通常の受理経路での関数呼び出しを減らします。
`log`、`exp`、`sqrt` は従来どおり使用し、近似式への置換は行いません。

```fortran
call rng%set_algorithm(normal_algorithm_ziggurat)
```

## MvNormal の変換

Fortran の配列は列優先なので、Cholesky 因子 `lower(i,j)` も列優先で保持します。

`sample_inplace` は標準正規乱数を `output` に直接生成し、列 `j` を大きい番号から処理します。
列 `j` の処理前には `output(j)` がまだ `z(j)` なので、それをローカル変数に退避してから `output(j)` を平均値で置き換えます。
その後、行 `i` を内側にして次を累積します。

```text
do j = n, 1, -1
  z_j = output(j)
  output(j) = mean(j)
  do i = j, n
    output(i) = output(i) + lower(i,j) * z_j
  end do
end do
```

この順序では `lower(i,j)` と `output(i)` の内側ループが連続アクセスになります。
保守性を優先し、手動のブロック化は行わず1列ずつ処理します。
追加の作業ベクトルやサンプルごとのヒープ確保はありません。
通常の `do` を使い、`do concurrent` や OpenMP による並列化は行いません。
共通 runner のコンパイル条件は `-std=f2023 -O3` のままで、SIMD 化はコンパイラの自動最適化に任せます。
非連続な配列区間も、公開 API を変えずに処理できます。

`normal_rng_t` は `sample_inplace` または `sample_into` に明示的に渡します。
そのため、分布オブジェクトと乱数状態を分離して管理できます。

## 再現性

同じシード、同じコンパイラ、同じ浮動小数点最適化条件であれば、同じ乱数列を得られます。
自前実装の xorshift64 の状態更新とシードは他言語と共通ですが、数学関数、浮動小数点演算、加算順序の違いにより、言語間のチェックサム一致は保証しません。
polar の分割生成では保存済みの値を先に使うよう修正したため、奇数個の生成を挟む呼び出し列の結果は修正前から変わります。
